## 1. 问题一：API Key 配置为环境变量

### 1.1 结论

沿用项目已有的 viper 约定（前缀 `AIJIAOXUE_`、层级下划线连接），在 `config.yaml` 中**只留空占位**，
真实 Key 通过环境变量 `AIJIAOXUE_TRANSCRIPTION_API_KEY` 注入。**但有一个必须避开的 viper 陷阱**（见 1.2），
否则环境变量会被静默忽略、Key 恒为空字符串，这是最容易踩且最难排查的坑。

### 1.2 🔴 已验证的陷阱：`AutomaticEnv` + `Unmarshal` 不认新键

项目现有写法是：

```go
v.SetEnvPrefix("AIJIAOXUE")
v.SetEnvKeyReplacer(strings.NewReplacer(".", "_"))
v.AutomaticEnv()
// ...
v.Unmarshal(&cfg)   // ← 问题在这里
```

`viper.Unmarshal` 走的是 `AllSettings()`，而 `AllSettings()` 只会遍历 `AllKeys()`——
**即"在 config.yaml 里出现过、或调用过 `SetDefault`/`BindEnv`"的键**。纯粹靠 `AutomaticEnv` 发现的键不在 `AllKeys()` 里，
`Unmarshal` 直接跳过。所以新增的 `transcription.apiKey` 如果不显式注册，环境变量**永远不会生效**。

我用项目真实的 `config.yaml` 和 viper 1.18.2 实测（`go run` 临时程序，已删除）：

```
不注册 default : apiKey="" workspaceId=""          ← 环境变量被静默丢弃
注册 default   : apiKey="sk-from-env-123" workspaceId="ws-from-env-456"
BindEnv 显式名 : apiKey="sk-bindenv-works" workspaceId="ws-bindenv-works"
```

**结论：必须 `SetDefault` 或 `BindEnv`，二选一（推荐 `BindEnv`，变量名更规范）。**

还有一个连带陷阱：viper 的 `SetEnvKeyReplacer` 只把 `.` 换成 `_`，**不会拆驼峰**。
所以 `transcription.apiKey` 自动推导出的名字是 `AIJIAOXUE_TRANSCRIPTION_APIKEY`（`APIKEY` 连写，中间没有下划线）。
写成直觉上的 `..._API_KEY` 会失效。用 `BindEnv` 显式指定即可消除这个歧义。

### 1.3 具体改动

**① `backend/internal/config/config.go`** —— 扩展结构体：

```go
// TranscriptionConfig 描述课堂音频转写（ASR）引擎参数（Sprint 2.2 阶段②）。
//
// 安全约定：APIKey 只允许来自环境变量 AIJIAOXUE_TRANSCRIPTION_API_KEY，
// config.yaml 中保持空串；本结构体禁止出现在任何 DTO 或日志字段中。
type TranscriptionConfig struct {
	Enabled         bool   `mapstructure:"enabled"`
	Engine          string `mapstructure:"engine"`         // 逻辑引擎名，写入 transcripts.engine
	EngineVersion   string `mapstructure:"engineVersion"`  // 写入 transcripts.engine_version
	Model           string `mapstructure:"model"`          // 如 qwen-audio-3.1-asr-flash-filetrans
	APIKey          string `mapstructure:"apiKey"`         // 仅环境变量注入
	WorkspaceID     string `mapstructure:"workspaceId"`    // 百炼业务空间 ID（可选）
	BaseURL         string `mapstructure:"baseUrl"`        // 空则按 WorkspaceID 推导
	Timeout         string `mapstructure:"timeout"`        // 单任务总超时，如 "30m"
	PollInterval    string `mapstructure:"pollInterval"`   // 轮询间隔，如 "5s"
	MaxConcurrency  int    `mapstructure:"maxConcurrency"` // 并发转写上限，保护内存与配额
	Diarization     bool   `mapstructure:"diarization"`    // 说话人分离（师生话轮比需要）
	StudentNames    []string `mapstructure:"studentNames"` // 脱敏词典（可选，见 §3.4）
}

// TimeoutDuration 解析转写总超时，缺省 30 分钟。
func (t TranscriptionConfig) TimeoutDuration() time.Duration {
	d, err := time.ParseDuration(t.Timeout)
	if err != nil || d <= 0 {
		return 30 * time.Minute
	}
	return d
}

// PollIntervalDuration 解析轮询间隔，缺省 5 秒。
func (t TranscriptionConfig) PollIntervalDuration() time.Duration {
	d, err := time.ParseDuration(t.PollInterval)
	if err != nil || d <= 0 {
		return 5 * time.Second
	}
	return d
}

// MaskedAPIKey 仅用于日志/排障，绝不返回给前端。
func (t TranscriptionConfig) MaskedAPIKey() string {
	if t.APIKey == "" {
		return "(未配置)"
	}
	if len(t.APIKey) <= 8 {
		return "***"
	}
	return t.APIKey[:6] + "***" + t.APIKey[len(t.APIKey)-4:]
}
```

而不是等到督导上传 45 分钟音频后才在 `transcripts.error_message` 里发现。

### 1.5 安全与稳定性的硬要求

| 项 | 要求 |
|---|---|
| **绝不回传前端** | `TranscriptionConfig` 不进任何 DTO；管理接口如日后新增，只返回 `MaskedAPIKey()` |
| **绝不入日志** | `slog` 记配置时统一打 `MaskedAPIKey()`；ASR 错误信息落 `transcripts.error_message` 前必须过滤掉 `Authorization` 头内容 |
| **不进代码库** | `config.yaml` 已在 `.gitignore`；**`AImodel/` 目前是未跟踪目录且含明文 Key，必须先处理（见 1.6）** |
| **超时** | 每次 `Transcribe` 都带 `context.WithTimeout`，`http.Client` 也设 `Timeout`，否则督导上传后 goroutine 永久挂起 |
| **并发上限** | `maxConcurrency` 信号量，避免 10 个 100MB 音频同时进内存 |
| **重试** | 仅对网络错误/5xx/`PENDING` 超时做 2 次指数退避重试；`FAILED` 子任务不重试（重试交给用户点「重试」按钮 → `POST /sessions/:id/transcript/retry`） |
| **降级** | 失败只写 `transcripts.status='failed'` + `error_message`，**绝不影响督导评分主流程**（`Sprint2-3` §4.4 硬约束）；对外可映射 `50003` |
| **重启恢复** | 进程重启会把 `running` 状态的任务变成僵尸。启动时执行一次清扫重新入队（见 §3.3） |

## 2. 问题二：音频文件存储与网页播放

### 2.1 结论：存储已经做对了，播放链路有一个真问题

**存储**（`recordingService.Upload` 已实现，方向正确）：

```
backend/uploads/recordings/{sessionID}/{uuid}.{ext}
```

- 落盘用 **UUID 文件名**，原始文件名只存库（`recordings.original_name`）——同时避免了路径穿越、重名覆盖与中文/特殊字符问题；
- 入库前做扩展名白名单（`mp3/wav/m4a`）+ 大小上限 + 内容嗅探（拒绝 `text/html`）；
- 一节课一条主录音（`uk_rec_session` 唯一约束），重复上传返回 409；
- 落库失败会 `os.Remove` 回滚已写文件；
- 播放写 `recording_playback_logs` 审计（合规要求，`Sprint2-3` §5.2-2）。

**播放**：`GET /api/v1/recordings/:id/stream` 用 `http.ServeFile` 提供，**服务端天生支持 Range**，
并且已设置 `Accept-Ranges: bytes` 与正确的 `Content-Type`。这部分也是对的。

**但是 —— 前端把 Range 废掉了。** `frontend/src/components/session/AudioPlayer.vue` 当前是：

```ts
const response = await fetch(props.src, { headers: { Authorization: `Bearer ...` } })
objectURL = URL.createObjectURL(await response.blob())   // ← 整包下载
```

`<audio>` 无法携带 `Authorization` 头，所以作者改用 `fetch` 手动带头——这解决了鉴权，却带来三个后果：

1. **完全没有流式**：45 分钟、约 20–45MB 的音频必须**全部下载完**才能开始播放，用户看到的是一段长时间的空白；
2. **内存峰值高**：整包进 `Blob` + 内存副本，多标签页并发时更明显；
3. **Range 请求形同虚设**，与接口契约（`Sprint2-3` §4.3「音频流式播放，支持 Range」）不符；
4. 附带：登录过期时 `if (!response.ok) return` **静默返回**，不走 axios 拦截器，用户只看到一个空播放器，没有任何提示。

### 2.2 推荐方案：短时「播放票据」+ 原生 `<audio>` 流式播放

思路：给每条录音签发一个**绑定到具体录音 id、短时有效、只能用于播放**的票据，
放进查询串（`?ticket=`），让 `<audio>` 原生发请求 → 服务端 Range 正常工作。

**① `backend/pkg/jwtutil/jwtutil.go`** —— 扩展 claims 并新增票据签发（向后兼容，旧令牌 `Scope` 为空即会话令牌）：

```go
// Claims 是「爱教学」使用的 JWT 载荷。
type Claims struct {
	Role   string `json:"role"`
	DeptID uint64 `json:"did"`
	Scope  string `json:"scp,omitempty"` // 空 = 会话令牌；"playback" = 音频播放票据
	RecID  uint64 `json:"rid,omitempty"` // 播放票据绑定的录音 id
	jwt.RegisteredClaims
}

// IsPlaybackTicket 判断是否为播放票据。
func (c *Claims) IsPlaybackTicket() bool { return c.Scope == "playback" }

// SignPlayback 签发短时播放票据：绑定用户、角色、院系与录音 id，只能用于该录音的流式播放。
// 注意 TTL 必须覆盖整段播放：<audio> 播放期间会持续发出多个 Range 请求，
// 每个请求都要重新校验票据，票据中途过期会导致播放中断。
func (m *Manager) SignPlayback(userID uint64, role string, deptID, recordingID uint64, ttl time.Duration, now time.Time) (string, error) {
	claims := Claims{
		Role:   role,
		DeptID: deptID,
		Scope:  "playback",
		RecID:  recordingID,
		RegisteredClaims: jwt.RegisteredClaims{
			Subject:   strconv.FormatUint(userID, 10),
			IssuedAt:  jwt.NewNumericDate(now),
			ExpiresAt: jwt.NewNumericDate(now.Add(ttl)),
		},
	}
	return jwt.NewWithClaims(jwt.SigningMethodHS256, claims).SignedString(m.secret)
}
```

**② `backend/internal/middleware/auth.go`** —— 增加「头优先、票据回退」的中间件，仅用于流式路由：

```go
// AuthOrPlaybackTicket 与 Auth 等价，但允许用 ?ticket= 短时票据鉴权。
// 仅挂在 GET /recordings/:id/stream：<audio> 标签无法自定义请求头，只能靠查询串。
// 票据必须 scope=playback，且 rid 与路径 :id 一致，防止拿 A 的票据听 B 的录音。
func AuthOrPlaybackTicket(manager *jwtutil.Manager) gin.HandlerFunc {
	return func(c *gin.Context) {
		token := ""
		if raw := c.GetHeader("Authorization"); strings.HasPrefix(strings.ToLower(raw), "bearer ") {
			token = strings.TrimSpace(raw[len("Bearer "):])
		} else if t := c.Query("ticket"); t != "" {
			token = t
		}
		if token == "" {
			response.Fail(c, errcode.New(errcode.Unauthorized, errcode.Unauthorized.Message()))
			c.Abort()
			return
		}
		claims, err := manager.Parse(token)
		if err != nil {
			response.Fail(c, errcode.New(errcode.Unauthorized, errcode.Unauthorized.Message()))
			c.Abort()
			return
		}
		// 走票据通道时必须校验录音 id 绑定，防止越权重放。
		if claims.IsPlaybackTicket() {
			id, err := strconv.ParseUint(c.Param("id"), 10, 64)
			if err != nil || claims.RecID != id {
				response.Fail(c, errcode.New(errcode.Unauthorized, errcode.Unauthorized.Message()))
				c.Abort()
				return
			}
		}
		userID, err := claims.UserID()

			response.Fail(c, errcode.New(errcode.Unauthorized, errcode.Unauthorized.Message()))
			c.Abort()
			return
		}
		c.Set(ctxUserID, userID)
		c.Set(ctxRole, claims.Role)
		c.Set(ctxDeptID, claims.DeptID)
		c.Next()
	}
}
```

**为什么不直接用 `?token=<会话 JWT>`**：会话 JWT 有效期 24h，放进 URL 会经浏览器历史、
`Referer`、Nginx access log 三处外泄，等于把整账号凭据写在 URL 里。播放票据把影响面收敛到
「一条录音 × 4 小时」，且 `rid` 绑定杜绝横向重放，是成本最低的正确解。若想更省事，
可把 TTL 缩短到 30 分钟并在 `<audio onerror>` 里重新拉 `Media` 续签，但复杂度反而更高。

**⑥ 🔴 必改项：查询串会进访问日志，票据必须脱敏**

`backend/internal/middleware/logger.go` 当前把完整查询串写进结构化日志：

```go
path := c.Request.URL.Path
if query := c.Request.URL.RawQuery; query != "" {
	path = path + "?" + query        // ← ?ticket=eyJhbGci... 会被完整落盘
}
```

票据一旦进日志，等于把「能听这条录音的凭据」写进了日志文件——鉴权形同虚设，且日志通常比
Key 的访问范围更广（运维、日志采集平台都能看）。必须改为对敏感参数做掩码：

```go
// internal/middleware/logger.go —— 记录路径时对敏感查询参数脱敏
func redactQuery(rawQuery string) string {
	if rawQuery == "" {
		return ""
	}
	values, err := url.ParseQuery(rawQuery)
	if err != nil {
		return "?<unparsable>"
	}
	for _, key := range []string{"ticket", "token", "api_key", "apikey"} {
		if values.Has(key) {
			values.Set(key, "***")
		}
	}
	return "?" + values.Encode()
}
```

调用处改为 `path = path + redactQuery(c.Request.URL.RawQuery)`。
这是本方案**唯一一处必须在接线时同步修改**的既有代码，漏改则票据机制失去意义。

### 2.3 存储层建议补齐的四点

| # | 问题 | 建议 |
|---|---|---|
| 1 | `recordings.file_path` 存的是**含 `upload.dir` 的相对路径**（如 `uploads/recordings/1/x.m4a`）。进程 cwd 一变（systemd 未设 `WorkingDirectory`、容器挂载点不同）就全部 404 | 库里只存**相对录音根的 key**（`recordings/1/x.m4a`）；读取时 `filepath.Join(cfg.Upload.Dir, key)`。并在 `Load()` 中用 `filepath.Abs` 把 `upload.dir` 归一化为绝对路径 |
| 2 | `duration_sec` 恒为 0（前端 `AudioPlayer` 拿不到时长，也没有时长校验） | ASR 返回的 `properties.original_duration_in_milliseconds` 直接回写 `recordings.duration_sec`，零成本 |
| 3 | 合规要求「保留期限：如 1 学期后归档或删除」（§5.2-3），当前无任何清理机制 | 加一个定时任务（每日一次）扫描超期 `recordings`，软删记录 + 删文件；`transcripts` 随之外键级联前需先决策（建议转写文本保留、音频删除，用于教学改进） |
| 4 | 生产环境由 Go 进程 `ServeFile` 转发大文件，占用应用进程带宽与连接 | 生产用 Nginx 内部重定向卸载：`X-Accel-Redirect` + `internal` location，Go 只负责鉴权与设头。开发环境维持现状即可 |

### 2.4 其他相关小问题

- `sniffAudio` 只拒绝 `text/*` 与 `html`，对 `.mp3` 改名伪装基本无效。真正的校验应交给 ASR 服务
  （模型会返回格式错误），或引入 `gabriel-vasile/mimetype`（已是间接依赖）做魔数校验；
- `copyMultipart` 用 `os.Create`（0644）且无 `Sync`，断电可能留下半截文件。建议 `os.OpenFile(..., 0o640)` + `f.Sync()`；
- `Upload` 中 `go s.processTranscript(context.Background(), transcript.ID, sessionID)` —— **第二个参数传的是 `sessionID`，
  但方法签名第二个参数是录音 id 且被忽略（`_ uint64`）**。接线时务必改成 `record.ID`，否则 ASR 拿不到文件路径；
- `Upload` 失败回滚只删新文件。若产品后续要支持「重传覆盖」，需显式删除旧文件与旧转写，当前契约是 409，无需处理。

### 3.1 新增 `backend/internal/asr/client.go`

按 `AImodel/audio/asr_test.py` 已验证的四步流程，改写为生产级 Go 客户端：
取上传凭证 → 传 OSS 拿 `oss://` 临时 URL → 提交异步任务 → 轮询 → 下载结果 JSON。

> 下面的代码已在本地用 `gofmt` + `go vet` 实际校验通过（提取本代码块、替换掉
> `internal/config` 依赖后编译），可直接落盘使用。

```go
// Package asr 是语音识别（ASR）适配层：把本地音频文件转成带时间戳的文本。
//
// 依赖方向：service → asr（叶子包，不反向依赖 service/handler）。
// 设计要点：调用方只传文件路径与 context；鉴权、重试、轮询、结果解析全部内聚在此。
// 本包不得记录 APIKey。
package asr

import (
	"bytes"
	"context"
	"encoding/json"
	"errors"
	"fmt"
	"io"
	"mime/multipart"
	"net/http"
	"net/url"
	"os"
	"path/filepath"
	"time"

	"aijiaoxue-api/internal/config"
)

// ErrEngineUnavailable 表示引擎侧不可用（未配置、鉴权失败、上游 5xx、任务超时）。
// service 层据此映射 50003 / transcripts.status='failed'。
var ErrEngineUnavailable = errors.New("asr: 引擎不可用")

const (
	policyURL  = "https://dashscope.aliyuncs.com/api/v1/uploads"
	publicBase = "https://dashscope.aliyuncs.com"
)

// Segment 是一句转写结果，Start/End 单位为秒（与 dto.TranscriptSegment 对齐）。
type Segment struct {
	Start   float64
	End     float64
	Speaker string
	Text    string
}

// Result 是一次转写的完整产物。
type Result struct {
	Content    string    // 纯文本全文
	Segments   []Segment // 句级分段
	DurationMS int       // 原始音频时长（毫秒），用于回写 recordings.duration_sec
}

// Client 是 DashScope 非实时语音识别（Filetrans）HTTP 客户端。
type Client struct {
	apiKey   string
	model    string
	baseURL  string
	diarize  bool
	timeout  time.Duration
	interval time.Duration
	http     *http.Client
}

// NewClient 依据配置构造客户端；配置不完整时返回 nil，由调用方降级。
func NewClient(cfg config.TranscriptionConfig) *Client {
	if !cfg.Enabled || cfg.APIKey == "" || cfg.Model == "" {
		return nil
	}
	base := cfg.BaseURL
	if base == "" {
		if cfg.WorkspaceID != "" {
			// 业务空间专属域名（华北2-北京）；公共域名亦可，见官方文档“接口地址”。
			base = fmt.Sprintf("https://%s.cn-beijing.maas.aliyuncs.com", cfg.WorkspaceID)
		} else {
			base = publicBase
		}
	}
	return &Client{
		apiKey:   cfg.APIKey,
		model:    cfg.Model,
		baseURL:  base,
		diarize:  cfg.Diarization,
		timeout:  cfg.TimeoutDuration(),
		interval: cfg.PollIntervalDuration(),
		// 单次 HTTP 交互超时；总时长由外层 context 控制。
		http: &http.Client{Timeout: 5 * time.Minute},
	}
}

// Transcribe 走完「上传 → 提交 → 轮询 → 下载」全流程。
func (c *Client) Transcribe(ctx context.Context, filePath string) (*Result, error) {
	ossURL, err := c.upload(ctx, filePath)
	if err != nil {
		return nil, err
	}
	taskID, err := c.submit(ctx, ossURL)
	if err != nil {
		return nil, err
	}
	transcriptionURL, err := c.poll(ctx, taskID)
	if err != nil {
		return nil, err
	}
	return c.fetchResult(ctx, transcriptionURL)
}

// --- 步骤 1：取上传凭证并上传到 DashScope 临时存储 ---

func (c *Client) upload(ctx context.Context, filePath string) (string, error) {
	u, _ := url.Parse(policyURL)
	q := u.Query()
	q.Set("action", "getPolicy")
	q.Set("model", c.model)
	u.RawQuery = q.Encode()

	req, _ := http.NewRequestWithContext(ctx, http.MethodGet, u.String(), nil)
	req.Header.Set("Authorization", "Bearer "+c.apiKey)
	resp, err := c.http.Do(req)
	if err != nil {
		return "", fmt.Errorf("%w: 获取上传凭证: %v", ErrEngineUnavailable, err)
	}
	defer resp.Body.Close()
	if resp.StatusCode != http.StatusOK {
		// 响应体可能含细节，但不含 Key；截断后返回便于排障。
		return "", fmt.Errorf("%w: 获取上传凭证 HTTP %d: %s", ErrEngineUnavailable, resp.StatusCode, snippet(resp.Body))
	}

	var policyResp struct {
		Data struct {
			UploadHost          string `json:"upload_host"`
			UploadDir           string `json:"upload_dir"`
			OSSAccessKeyID      string `json:"oss_access_key_id"`
			Signature           string `json:"signature"`
			Policy              string `json:"policy"`
			XOSSAcl             string `json:"x_oss_object_acl"`
			XOSSForbidOverwrite string `json:"x_oss_forbid_overwrite"`
		} `json:"data"`
	}
	if err := json.NewDecoder(resp.Body).Decode(&policyResp); err != nil {
		return "", fmt.Errorf("%w: 解析上传凭证: %v", ErrEngineUnavailable, err)
	}
	p := policyResp.Data

	f, err := os.Open(filePath)
	if err != nil {
		return "", fmt.Errorf("asr: 打开音频失败: %w", err)
	}
	defer f.Close()

	key := fmt.Sprintf("%s/%s", p.UploadDir, filepath.Base(filePath))
	var body bytes.Buffer
	w := multipart.NewWriter(&body)
	fields := map[string]string{
		"OSSAccessKeyId":         p.OSSAccessKeyID,
		"Signature":              p.Signature,
		"policy":                 p.Policy,
		"x-oss-object-acl":       p.XOSSAcl,
		"x-oss-forbid-overwrite": p.XOSSForbidOverwrite,
		"key":                    key,
		"success_action_status":  "200",
	}
	for k, v := range fields {
		_ = w.WriteField(k, v)
	}
	part, err := w.CreateFormFile("file", filepath.Base(filePath))
	if err != nil {
		return "", fmt.Errorf("%w: 构造上传表单: %v", ErrEngineUnavailable, err)
	}
	if _, err := io.Copy(part, f); err != nil {
		return "", fmt.Errorf("asr: 读取音频失败: %w", err)
	}
	_ = w.Close()

	upReq, _ := http.NewRequestWithContext(ctx, http.MethodPost, p.UploadHost, &body)
	upReq.Header.Set("Content-Type", w.FormDataContentType())
	upResp, err := c.http.Do(upReq)
	if err != nil {
		return "", fmt.Errorf("%w: 上传音频: %v", ErrEngineUnavailable, err)
	}
	defer upResp.Body.Close()
	if upResp.StatusCode != http.StatusOK {
		return "", fmt.Errorf("%w: 上传音频 HTTP %d: %s", ErrEngineUnavailable, upResp.StatusCode, snippet(upResp.Body))
	}
	return "oss://" + key, nil
}

// --- 步骤 2：提交异步识别任务 ---

func (c *Client) submit(ctx context.Context, ossURL string) (string, error) {
	// 说话人分离仅支持单声道，由配置显式开启。
	params := map[string]any{"channel_id": []int{0}}
	if c.diarize {
		params["diarization_enabled"] = true
	}
	payload := map[string]any{
		"model":      c.model,
		"input":      map[string]any{"file_urls": []string{ossURL}},
		"parameters": params,
	}
	buf, _ := json.Marshal(payload)

	req, _ := http.NewRequestWithContext(ctx, http.MethodPost,
		c.baseURL+"/api/v1/services/audio/asr/transcription", bytes.NewReader(buf))
	req.Header.Set("Authorization", "Bearer "+c.apiKey)
	req.Header.Set("Content-Type", "application/json")
	req.Header.Set("X-DashScope-Async", "enable")
	// 使用 oss:// 临时 URL 时必须携带；缺失会被上游拒绝。
	req.Header.Set("X-DashScope-OssResourceResolve", "enable")

	resp, err := c.http.Do(req)
	if err != nil {
		return "", fmt.Errorf("%w: 提交识别任务: %v", ErrEngineUnavailable, err)
	}
	defer resp.Body.Close()
	if resp.StatusCode != http.StatusOK {
		return "", fmt.Errorf("%w: 提交识别任务 HTTP %d: %s", ErrEngineUnavailable, resp.StatusCode, snippet(resp.Body))
	}
	var out struct {
		Output struct {
			TaskID     string `json:"task_id"`
			TaskStatus string `json:"task_status"`
		} `json:"output"`
	}
	if err := json.NewDecoder(resp.Body).Decode(&out); err != nil || out.Output.TaskID == "" {
		return "", fmt.Errorf("%w: 解析 task_id 失败: %v", ErrEngineUnavailable, err)
	}
	return out.Output.TaskID, nil
}

// --- 步骤 3：轮询任务状态（受 ctx 总超时保护） ---

func (c *Client) poll(ctx context.Context, taskID string) (string, error) {
	ticker := time.NewTicker(c.interval)
	defer ticker.Stop()
	for {
		req, _ := http.NewRequestWithContext(ctx, http.MethodGet, c.baseURL+"/api/v1/tasks/"+taskID, nil)
		req.Header.Set("Authorization", "Bearer "+c.apiKey)
		resp, err := c.http.Do(req)
		if err != nil {
			return "", fmt.Errorf("%w: 查询任务: %v", ErrEngineUnavailable, err)
		}
		var out struct {
			Output struct {
				TaskStatus string `json:"task_status"`
				Results    []struct {
					SubtaskStatus    string `json:"subtask_status"`
					Code             string `json:"code"`
					Message          string `json:"message"`
					TranscriptionURL string `json:"transcription_url"`
				} `json:"results"`
			} `json:"output"`
		}
		decodeErr := json.NewDecoder(resp.Body).Decode(&out)
		resp.Body.Close()
		if decodeErr != nil {
			return "", fmt.Errorf("%w: 解析任务状态: %v", ErrEngineUnavailable, decodeErr)
		}

		switch out.Output.TaskStatus {
		case "SUCCEEDED":
			for _, r := range out.Output.Results {
				if r.SubtaskStatus == "SUCCEEDED" && r.TranscriptionURL != "" {
					return r.TranscriptionURL, nil
				}
				return "", fmt.Errorf("%w: 子任务失败 code=%s message=%s", ErrEngineUnavailable, r.Code, r.Message)
			}
			return "", fmt.Errorf("%w: 任务成功但无结果", ErrEngineUnavailable)
		case "FAILED", "CANCELED":
			return "", fmt.Errorf("%w: 任务状态 %s", ErrEngineUnavailable, out.Output.TaskStatus)
		}

		select {
		case <-ctx.Done():
			return "", fmt.Errorf("%w: 轮询超时: %v", ErrEngineUnavailable, ctx.Err())
		case <-ticker.C:
		}
	}
}

// --- 步骤 4：下载并解析识别结果 ---

func (c *Client) fetchResult(ctx context.Context, transcriptionURL string) (*Result, error) {
	req, _ := http.NewRequestWithContext(ctx, http.MethodGet, transcriptionURL, nil)
	resp, err := c.http.Do(req)
	if err != nil {
		return nil, fmt.Errorf("%w: 下载识别结果: %v", ErrEngineUnavailable, err)
	}
	defer resp.Body.Close()
	if resp.StatusCode != http.StatusOK {
		return nil, fmt.Errorf("%w: 下载识别结果 HTTP %d", ErrEngineUnavailable, resp.StatusCode)
	}

	var raw struct {
		Properties struct {
			OriginalDurationMS int `json:"original_duration_in_milliseconds"`
		} `json:"properties"`
		Transcripts []struct {
			Text      string `json:"text"`
			Sentences []struct {
				BeginTime int    `json:"begin_time"` // 毫秒
				EndTime   int    `json:"end_time"`   // 毫秒
				Text      string `json:"text"`
				SpeakerID *int   `json:"speaker_id"` // 未开启说话人分离时缺省
			} `json:"sentences"`
		} `json:"transcripts"`
	}
	if err := json.NewDecoder(resp.Body).Decode(&raw); err != nil {
		return nil, fmt.Errorf("%w: 解析识别结果: %v", ErrEngineUnavailable, err)
	}

	res := &Result{DurationMS: raw.Properties.OriginalDurationMS}
	var content bytes.Buffer
	for _, tr := range raw.Transcripts {
		if content.Len() > 0 {
			content.WriteString("\n")
		}
		content.WriteString(tr.Text)
		for _, s := range tr.Sentences {
			if s.Text == "" {
				continue
			}
			speaker := ""
			if s.SpeakerID != nil {
				// 转成「说话人1/2…」便于前端 TranscriptViewer 区分气泡。
				speaker = fmt.Sprintf("说话人%d", *s.SpeakerID+1)
			}
			res.Segments = append(res.Segments, Segment{
				Start:   float64(s.BeginTime) / 1000, // 毫秒 → 秒
				End:     float64(s.EndTime) / 1000,
				Speaker: speaker,
				Text:    s.Text,
			})
		}
	}
	res.Content = content.String()
	return res, nil
}

// snippet 截断上游响应体，避免把大段无关节流写进 error_message（VARCHAR(255)）。
func snippet(r io.Reader) string {
	b, _ := io.ReadAll(io.LimitReader(r, 200))
	return string(b)
}
```

```go
	jwt           *jwtutil.Manager   // 签发播放票据（§2.2）

	timeout       time.Duration
}
```

`processTranscript` 从空壳改为真实实现：

```go
// processTranscript 是 ASR 异步任务体：与督导评分主链路完全解耦，
// 任何失败只落到 transcripts.status='failed'，绝不向上传播。
func (s *recordingService) processTranscript(ctx context.Context, transcriptID, recordingID uint64) {
	ctx, cancel := context.WithTimeout(ctx, s.transcription.TimeoutDuration())
	defer cancel()

	if err := s.recordings.UpdateTranscript(ctx, transcriptID,
		map[string]any{"status": model.TranscriptRunning, "error_message": ""}); err != nil {
		slog.Error("转写状态置 running 失败", "transcriptID", transcriptID, "err", err)
		return
	}

	fail := func(reason string) {
		// error_message 仅 VARCHAR(255)，先截断，避免上游长响应把写入打挂。
		if len(reason) > 255 {
			reason = reason[:255]
		}
		_ = s.recordings.UpdateTranscript(ctx, transcriptID,
			map[string]any{"status": model.TranscriptFailed, "error_message": reason})
		slog.Warn("转写失败", "transcriptID", transcriptID, "reason", reason)
	}

	if s.transcriber == nil {
		fail("ASR 引擎未配置")
		return
	}

	rec, err := s.recordings.GetRecording(ctx, recordingID)
	if err != nil {
		fail("查询录音失败")
		return
	}

	// 并发闸门：拿不到令牌就排队，避免同时把多个大文件推进内存。
	select {
	case s.sem <- struct{}{}:
		defer func() { <-s.sem }()
	case <-ctx.Done():
		fail("转写排队超时")
		return
	}

	res, err := s.transcriber.Transcribe(ctx, rec.FilePath)
	if err != nil {
		// 不外泄上游原始报文，只记类别。
		fail("语音识别调用失败")
		slog.Error("ASR 调用失败", "transcriptID", transcriptID, "recordingID", recordingID, "err", err)
		return
	}

	// 合规 §5.2-5：落库前必须做学生姓名脱敏。
	content, segments := desensitize(res.Content, res.Segments, s.transcription.StudentNames)
	segJSON, err := json.Marshal(segments)
	if err != nil {
		fail("转写分段序列化失败")
		return
	}
	segStr := string(segJSON)
	if err := s.recordings.UpdateTranscript(ctx, transcriptID, map[string]any{
		"content":        content,
		"segments":       segStr,
		"engine":         s.transcription.Engine,
		"engine_version": s.transcription.EngineVersion,
		"status":         model.TranscriptDone,
		"error_message":  "",
	}); err != nil {
		slog.Error("写入转写结果失败", "transcriptID", transcriptID, "err", err)
		return
	}

	// 顺带回写时长，前端播放器与时长校验都需要（§2.3-2）。
	if res.DurationMS > 0 {
		_ = s.recordings.UpdateRecordingDuration(ctx, recordingID, res.DurationMS/1000)
	}
}
```

同时把 `Upload` 里的分发参数改对（当前传的是 `sessionID`，详见 §2.4）：

```go
	// 注意：第二个参数必须是录音 id，转写任务要靠它取文件路径。
	go s.processTranscript(context.Background(), transcript.ID, record.ID)
```

### 3.3 重启恢复：清扫僵尸任务

进程在转写中途重启（这是**必然发生**的，`running` 会永久卡住）时，需要在启动时重新入队。
`cmd/server/main.go` 里 DB 就绪后调用一次：

```go
// repository
func (r *recordingRepository) ListStuckTranscripts(ctx context.Context) ([]model.Transcript, error) {
	var rows []model.Transcript
	// 上一进程中断时遗留的 running；pending 说明分发丢失，一并重排。
	err := r.db.WithContext(ctx).Where("status IN ?", []string{model.TranscriptRunning, model.TranscriptPending}).Find(&rows).Error
	return rows, err
}
```

```go
// service：启动时把僵尸任务重新入队（幂等，可重复调用）
func (s *recordingService) RequeueStuck(ctx context.Context) (int, error) {
	rows, err := s.recordings.ListStuckTranscripts(ctx)
	if err != nil {
		return 0, err
	}
	for _, tr := range rows {
		if err := s.recordings.UpdateTranscript(ctx, tr.ID,
			map[string]any{"status": model.TranscriptPending, "error_message": ""}); err != nil {
			continue
		}
		go s.processTranscript(context.Background(), tr.ID, tr.RecordingID)
	}
	return len(rows), nil
}
```

> `cmd/server/main.go` 中调用后打一条结构化日志：`slog.Info("重启恢复：重新入队未完成转写", "count", n)`。

### 3.4 学生姓名脱敏（合规硬要求，§5.2-5）

这是**上线前必须落地**的一项，但需要你补一个信息源才能做准：学生名册目前不在库里
（`users` 表只有教师与督导）。当前可落地的最小实现是「词典 + 称谓正则」双规则，
抽象成接口以便后续换成真正的 NER（或调用 Qwen 文本模型做命名实体识别）：

```go
// internal/service/desensitize.go
//
// 脱敏策略（按优先级）：
//  1. 词典命中：优先替换 config.transcription.studentNames，以及数据库中的教师姓名；
//     长名优先，避免「张三」误伤「张三丰」。
//  2. 称谓正则：把「XXX同学 / XXX老师」中的 2–3 个汉字姓名替换为匿名代号。
// 局限：无法覆盖音近字误识别与未收录姓名。若需高准确率，应接入 NER 模型，
// 但**任何情况下都不得把带真实姓名的转写文本写入 transcripts.content**。
func desensitize(content string, segs []asr.Segment, dict []string) (string, []dto.TranscriptSegment)
```

映射规则：同一真实姓名始终映射到同一代号（保持话轮可读性），形如
`张伟→学生A`、`李娜→学生B`，教师本人 → `教师`。返回的 `segments` 与 `content` 必须**同步替换**，
否则前端气泡与全文会不一致。

> 如果暂时拿不到名册，建议先只开「称谓正则 + 教师姓名」两条规则，并在
> `transcripts.error_message` 不相关的前提下，于评估页显著位置保留
> 「仅用于教学支持，不作为考核依据」提示（§5.3）。

## 6. 风险与注意事项

1. **ASR 计费按「语音内容时长」而非文件时长**（非语音段不计费），评估成本时按语音时长估算；
2. **额度与限流**：`maxConcurrency` 需与百炼账号的并发配额匹配，超限会被上游 429，表现为 `transcripts.status='failed'`，
   建议对 429 单独做退避重试；
3. **音频时长上限**：开启说话人分离时官方建议不超过 2 小时；45 分钟课堂音频安全，但需在 `Upload` 层
   对超长音频提前拒绝（当前只校验了大小）；
4. **模型版本变更**：`transcripts.engine_version` 已记录模型名，切换模型（如 `fun-asr` 系列）时历史数据可追溯，
   但**不要**用不同模型的结果覆盖同一 `session_id` 的记录（`uk_tr_session` 会 upsert），需保留版本语义；
5. **教师端行为**：按权限矩阵，教师**不能听音频**但**能看自己的转写文本**（`GET /sessions/:id/transcript` 对教师开放，
   `GET /recordings/:id/stream` 对教师 403）。因此 `PlaybackURL` 只在督导侧填充，前端 `AudioPlayer` 也已用
   `v-if="isSupervisor"` 包裹，两条防线一致；
6. **智能体评分衔接**：转写 `done` 之后才是智能体评分的输入。当前 `evaluations` 的 agent 行写入
   属于同一阶段（`UpsertAgentEvaluation` 仓储方法已就绪），建议统一走「转写完成 → 触发评分」的事件点，
   避免在 `processTranscript` 里堆叠过多职责（可先写一个 `onTranscriptDone` 钩子占位）。

### 7.3 🔴 联调中发现并修复的两个真实缺陷

这两个缺陷**都只有端到端联调才能暴露**，单元测试与类型检查都无法发现，特此记录：

**缺陷 1：`transcripts.engine_version` 列宽不足，导致「付费成功但存不下来」**

原设计 `VARCHAR(32)`，而真实模型名 `qwen-audio-3.1-asr-flash-filetrans` 有 **34** 个字符：

```
Error 1406 (22001): Data too long for column 'engine_version' at row 1
```

MySQL 8 严格模式下超长直接报错，**整条 UPDATE 回滚**。危害远大于"少存一个字段"：

- ASR 已经调用成功、已经计费，但 `content` / `segments` **全部丢失**，需重新识别（再付一次费）；
- `status` 停留在 `running`，前端无限轮询、用户以为还在转写。

修复：`migrations/6_transcripts_engine_width.up.sql` 把 `engine` / `engine_version` 放宽到 `VARCHAR(64)`；
另加两道防线——`config.Load` 启动期校验模型名 ≤64 字符（**在付费之前**拦住），
以及最终写入失败时置 `failed` 而非留在 `running`。

**缺陷 2：流式路由挂在 `Auth` 组内，票据机制完全失效**

`/recordings/:id/stream` 最初注册在 `authed := v1.Group("", middleware.Auth(jwt))` 组内：

```go
authed.GET("/recordings/:id/stream", middleware.AuthOrPlaybackTicket(jwt), recordingH.Stream)
```

gin 会先执行**组上的** `Auth`，而 `Auth` 要求 `Authorization` 头 —— `<audio>` 恰恰带不了这个头，
于是请求在 `AuthOrPlaybackTicket` 运行之前就被 401 拒绝。表现为「票据签发正常、URL 正确，但音频就是播不出来」。

修复：把该路由移到 `v1` 上单独注册（见 `router.go` 注释），角色与数据范围校验仍由
`RecordingService.Stream` 在 service 层强制。

回归防护：新增 `internal/router/router_test.go`，用**不真正连接的 GORM 实例**装配真实路由表，
断言「无凭据 401、带有效票据不得 401」。只挂单个中间件的单元测试发现不了这个 bug，必须测真实路由表。

**缺陷 3：CORS 白名单漏掉内网 IP，表现为「页面能打开、一点登录就 403」**

浏览器验证阶段发现 `POST /auth/login` 连续返回 **403**（日志 16:55 有 5 次），
但登录是公开路由、与鉴权无关，实际是 CORS 中间件拦的：

```
Origin: http://localhost:5173        → 200
Origin: http://127.0.0.1:5173        → 200
Origin: http://172.22.81.206:5173    → 403   ← Vite 的 Network 地址
```

`cors.origins` 只配了 localhost / 127.0.0.1，而 Vite dev server 除 localhost 外还会监听内网 IP；
用内网地址打开页面时浏览器会带 `Origin: http://<内网IP>:5173`，不在白名单里即被拒。
**接口自测发现不了**：`curl` 不带 `Origin`，所以此前所有命令行验证都是 200。

修复：`CORSConfig` 新增 `allowAnyOrigin`（默认 `false`），本地 `config.yaml` 置 `true`，
中间件用 `AllowOriginFunc` 回显具体来源。注意**不能**写 `AllowOrigins: ["*"]`：
本服务 `AllowCredentials=true`，gin-contrib/cors 对「凭据 + 通配」会直接 panic。
启动时若开启该开关会打一条显著 WARN，生产必须关闭。

回归防护：`internal/middleware/cors_test.go` 覆盖白名单放行 / 名单外 403 / 无 Origin 不受影响 /
放行任意来源时回显具体来源 / OPTIONS 预检。
