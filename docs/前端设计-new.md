> **文档定位**：本文是前端信息架构与视觉风格的**目标态设计指导**，用于驱动下一轮前端优化开发。

## 1. 问题诊断：为什么现在的界面像「课程增删改查系统」

功能架构已经完备（评价闭环后端已落地、智能体接口已预留），但界面没有把这两件事「讲出来」。逐条对照现状：

| # | 症状 | 现状证据 | 后果 |
|---|------|---------|------|
| 1 | **导航按「资源类型」组织，而非按「质量评估旅程」组织** | 侧边栏 = 工作台 / 课程管理 / 教师管理 / 听评课管理（AppLayout.vue） | 用户心智模型是「这是个管课程的系统」，评估功能只是附属 |
| 2 | **评价功能埋在三级页面深处** | 督导评估路径：课程库 → 课程详情 → 历史授课记录 Tab → 当堂课评估页 | 系统的「核心动作」（评分）没有一级入口，首屏看不到任何评分数据 |
| 3 | **视觉是 Element Plus 默认风格的变体** | 浅色侧边栏 + 默认蓝 `#2F54EB` + el-card 白卡网格（tokens.scss） | 与任意一个后台管理系统撞脸，「学院蓝·清新教育」定位没有兑现为可感知的差异 |
| 4 | **评分数据没有成为视觉主角** | 综合分只是 StatCard 里的一个 28px 数字；五维分是普通条形 | 本项目最独特的资产——5 维锚点评分体系、督导×AI 双源融合、样本量透明——在视觉上全部不可辨识 |
| 5 | **AI 元素只有一行小字** | 智能体参考区是「AI 参考」文字 Tag + 占位说明 | 「AI 支持的教学提优」这一核心卖点，在界面上无任何专属视觉存在感 |
| 6 | **工作台是通用统计卡** | 三角色工作台 = 4 张 StatCard + 列表/入口卡（fetchDashboardApi） | 打开系统第一眼看到的仍是「课程数 / 班级数 / 资源数」这类 CRUD 计数，而非「质量」 |

**结论**：问题不在缺功能，而在**叙事错位**——界面把「课程管理」当主角、把「质量评估」当配角。重设计的本质是**交换主配角**。

## 2. 设计策略：一条核心叙事 + 三个视觉签名

### 2.1 核心叙事：「界面即测量仪器」

产品愿景是「让教学质量持续可测」。新界面要让人第一眼就理解平台的动作闭环：

```
   测            融              察              提
（督导锚点评分）（督导×AI 双源融合）（质量全景下钻）（AI 建议 + 对话）
      └────── 场次级 ──────┘        │               │
              └──── 课程级 ────────┤               │
                     └──── 教师级 ─┴── 趋势 ────────┘
```

- **测**：当堂课评估页是系统的「核心动作页」，锚点刻度可视化（§5.5）；
- **融**：综合分永远是「督导 × AI 双源罗盘」图形，而不是一个裸数字（§4.4）；
- **察**：工作台升级为「质量驾驶舱」，热力图 / 雷达 / 待评队列成为首屏主角（§5.3）；
- **提**：教师端首屏直达「我的质量档案」与 AI 提优建议，AI 视觉全链路可识别（§4.5 / §5.7）。

### 2.2 三个视觉签名（识别度的来源）

| 签名 | 图形 | 出现位置 | 传达的信息 |
|------|------|---------|-----------|
| **① 双源罗盘** | 内外双弧（督导弧·靛蓝 + AI 弧·亮紫）+ 中心综合分大数字 | 工作台、评估页、教师画像、提优页……所有综合分展示位 | 「这个分数 = 人 + AI 双源融合」，一眼看懂可信度结构 |
| **② 质量色阶 + 等级徽章** | 5 级色带（红→琥珀→绿）与「优秀/良好/合格/待改进/需干预」徽章 | 全部评分数字、维度条、热力图、状态流 | 分数可读化：不用记数值也知道好坏，色阶即品牌 |
| **③ AI 琥珀语言** | 四芒星徽标 + 亮紫渐变 + 浅紫虚线卡 + 流式光标 | AI 参考卡、AI 建议、AI 对话、转写区 | 「这是 AI 的产出，可参考、可追溯」，人机分工可视化 |

### 2.3 「不做清单」（与差异化同等重要）

- ❌ 不引入第二套 UI 库（Won't 约束继承），全部基于 Element Plus 2.7 + 自绘 SVG/CSS；
- ❌ 不改任何后端接口路径与 DTO；
- ❌ 不用玻璃拟态 / 大面积渐变 / 发光效果堆「AI 感」——AI 的识别度靠徽标与卡片语法，不靠特效；
- ❌ 不做移动端深度适配（桌面 ≥1280px 不变）；
- ❌ 不牺牲既有 143 项验收断言（`scripts/verify.sh`）——路由只增不改删。

### 3.3 新增路由决策：为什么教师需要 `/me/quality`

现状教师的提优数据挂在 `/courses/:id/improve`（课程视角），但「我的教学水平如何、最近哪些课被评了、AI 给了我什么建议」是**人视角**的问题。开发计划 §4.2 已预留教师查本人聚合的权限（`teacher（仅自己）`），且 `GET /teachers/:id/evaluations` 一次拉取即可渲染全部历次评价。因此：

- `/me/quality` = 教师的「质量主页」：综合分双源罗盘 + 五维 + 全部课程评分明细 + 评价时间线 + AI 建议摘要；
- 每门课程行 → 跳 `/courses/:id/improve`（课程级提优），层级关系清晰；
- 主任/督导的 `/teachers/:id` 是同一数据的不同视角（跨人 vs 本人），两页复用 `TeacherScorePanel` / `ScoreRadar` / 时间线组件，仅权限与叙事文案不同。

### 3.4 改造后的三条角色旅程

**① 主任 —— 察全局 → 看个人 → 追课次**

```
/dashboard 质量驾驶舱
  ├─ 本室质量热力（教师 × 五维矩阵，GET /teacher-scores）
  │     └─ 点任一教师 ─▶ /teachers/:id 教师画像（双源罗盘 + 维度条 + 时间线）
  │                          └─ 按课程明细 ─▶ /courses/:id ─▶ 历史授课记录 ─▶ /sessions/:id/evaluation（只读）
  └─ 课程库（统筹排课入口，降级为底座）
```

**② 督导 —— 评估是我的一级动作**

```
/dashboard 质量驾驶舱
  ├─ 待评课队列（本周计划/已完成状态流）
  └─▶ /supervision 课堂评估
        ├─ 待评队列：今日/本周 · 一步进评估页
        └─▶ /sessions/:id/evaluation 当堂课质量评估（锚点刻度 · 双源罗盘 · AI 参考 · 录音转写）
```

**③ 教师 —— 看自己 → 去提优**

```
/dashboard 质量驾驶舱（我的综合分罗盘 + 最近评价流）
  └─▶ /me/quality 我的质量档案（人视角：五维 + 全课程明细 + AI 建议摘要）
        └─▶ /courses/:id/improve 教学提优（课程视角：雷达驾驶舱 + 评语流 + AI 建议/对话）
```

## 4. 视觉风格体系

### 4.1 风格定位：「学术墨韵 × 评估仪器」

保留「专业可信」的高校气质，但把「清新教育」校准为「**严谨的测量感**」：

- **深色结构层**承载导航（墨海蓝侧边栏），把内容区让给数据；
- **评分数据用仪器级精度呈现**：等宽数字、色阶刻度、锚点文案，处处暗示「这是测量结果而非主观印象」；
- **AI 用琥珀紫渐变语言**统一显形，与「人类督导（靛蓝）」形成一眼可辨的双源对比；
- 层级靠留白与字重，装饰克制（无玻璃、无发光、无大面积渐变）。

**主色决策说明**：主操作色保留 `#2F54EB` 不动。理由：① 它同时是主任角色色与 Element 主题锚点，保留可使全部 el-* 组件零回归成本；② 辨识度不靠换主色，而靠下述「深色结构层 + 评分色阶 + AI 语言」三件签名（实践上换一个蓝并不能解决趋同，三个签名系统才能）。若后续团队希望进一步差异化，可评估把主色微调至更深的靛蓝 `#2A45C0`，属可选增强项。

### 4.2 色彩体系（tokens.scss 增量，见 §7 全量清单）

#### 4.2.1 新增：结构色（深色侧边栏 / 页头）

| Token | 值 | 用途 |
|-------|-----|------|
| `--color-ink` | `#0E1B2C` | 侧边栏/深色页头基底 |
| `--color-ink-2` | `#16283E` | 菜单悬停底 |
| `--color-ink-3` | `#1F3A5F` | 菜单激活底、深色内描边 |
| `--color-ink-text` | `#DCE7F5` | 侧栏主文字 |
| `--color-ink-text-dim` | `#8FA3BF` | 侧栏次级文字 |

深色侧边栏是「去掉 Element 默认脸」的性价比最高一步，且与评分色阶、AI 渐变天然协调。

#### 4.2.2 新增：AI 视觉色（人机双源对比的「机」侧）

| Token | 值 | 用途 |
|-------|-----|------|
| `--color-ai` | `#8B5CF6` | AI 锚点色（徽标、AI 弧、AI 文字强调） |
| `--color-ai-bright` | `#A855F7` | AI 徽标亮紫、悬停 |
| `--color-ai-deep` | `#6D28D9` | AI 描边、按下 |
| `--color-ai-bg` | `#F6F3FF` | AI 卡片浅底 |
| `--gradient-ai` | `linear-gradient(135deg, #6D28D9 0%, #A855F7 55%, #D946EF 100%)` | AI 徽标、AI 对话头像、AI 建议卡顶部饰条 |

> 与督导角色色 `#722ED1` 的区分约定：督导紫只出现在 `RoleTag` / 头像（指「人」）；AI 渐变紫只出现在智能体产出的内容上（指「机器产出」），且必配四芒星徽标与「AI 参考」文字徽章，两个场景不相交，不会混淆。

#### 4.2.3 新增：评分色阶（系统的第二主色）

| Token | 值 | 锚点等级 | 语义 |
|-------|-----|---------|------|
| `--color-score-5` | `#2FB344` | 优秀 | 可作为示范课 |
| `--color-score-4` | `#84B80C` | 良好 | 达到骨干教师水平 |
| `--color-score-3` | `#F5A623` | 合格 | 达到基本教学要求 |
| `--color-score-2` | `#F76707` | 待改进 | 存在明显短板 |
| `--color-score-1` | `#E5484D` | 不合格 | 需要立即干预 |
| `--color-score-void` | `#C9CDD4` | — | 无分数（`null` 专用，见红线 §8） |
| `--gradient-score` | `linear-gradient(90deg, #E5484D, #F5A623, #2FB344)` | | 连续分数色带（趋势图渐变、罗盘弧） |

**使用规则**：
- 离散分（1–5 原始分）：按上表直接映射；
- 连续分（0–100 综合分/维度分）：按五段区间映射色阶——`[0,40) score-1`、`[40,60) score-2`、`[60,75) score-3`、`[75,90) score-4`、`[90,100] score-5`（阈值与服务端锚点「3=合格」对齐：60 分即李克特 3 分）；
- **色阶只用于「分数及其派生物」**（数字、条形、雷达面积、热力、罗盘弧），禁止作装饰色——这是色阶可信度的前提。

#### 4.2.4 保留语义色

三角色色（`#2F54EB` / `#13C2C2` / `#722ED1`）、成功/警告/错误/信息色、文字与背景中性色全部沿用，不另起炉灶。

### 4.3 字体与数字（评分数字是主角）

```scss
--font-score: 'Bahnschrift', 'DIN Alternate', 'Segoe UI', sans-serif;  // 评分大数字（系统自带 DIN 风，零依赖兜底）
--font-size-score-xl: 40px;   // 双源罗盘中心综合分
--font-size-score-lg: 28px;   // StatCard 级评分
--font-size-score-md: 20px;   // 维度条端数字
```

- 评分数字一律 `font-variant-numeric: tabular-nums` + 字重 600（继承现有规范），字体走 `--font-score`；
- 评分数字**永远随附证据链**：数字旁必有等级徽章（§4.4）与样本量标注（红线继承）；
- 正文排版不变（14px 基准、1.6 行高），不引入新中文字体。

### 4.4 签名图形规范

#### 4.4.1 双源罗盘 `QualityCompass`

```
        ╭────督导弧（#2F54EB，按 supervisorScore 占比）────╮
        │  ╭──AI 弧（#8B5CF6，按 agentScore 占比）──╮     │
        │  │            82.5                      │     │
        │  │         良好 · 综合分                 │     │
        │  │   督导 85.0  ·  AI 80.0  ·  α=0.5    │     │
        │  ╰──────────────────────────────────────╯     │
        ╰────────────────────────────────────────────────╯
   样本：已评 3 / 5 场 · 对齐 3 · 样本充足 ✓
```

- **用途**：一切「综合分」展示位（工作台、画像、提优、评估页）统一用它替代裸数字；
- **规则**：
  - 中心 = `compositeScore` 大数字 + 质量等级徽章（连续分区间的等级文案）；
  - 双弧 = 双侧分，单侧 `null` 时只画一侧弧并显示「单源」提示；
  - 下方一行 = `sample`（evaluatedCount / sessionCount / alignedCount），`sampleSufficient === false` 时标「样本不足」琥珀徽章；
  - `flags` 非空时罗盘角落出现「口径提示」入口（点开显示 flag 的人话解释，继承 AGENTS §9.6-5「不得静默」）；
  - `compositeScore === null` → 整个罗盘退化为 `--color-score-void` 灰环 + 「暂无评价」，**禁止画 0**。

#### 4.4.2 五维雷达 `ScoreRadar`（升级）

- 五边形网格 + 评分色阶填充（分值越高绿色越深），顶点标短名（沿用 `EVALUATION_DIMENSIONS.shortName`）；
- **双源叠加**：督导侧实线填充、AI 侧虚线描边（有 agentScore 时叠加），人机差异一眼可见；
- `frontier` 顶点用「观星」样式（空心顶点 + 小星标）区别于四个计分维度，hover 提示「观测项 · 不计分」；
- 每个顶点旁可挂权重徽章（`30% / 30% / 20% / 20% / 观测`），强化「加权体系」的仪器感。

#### 4.4.3 锚点刻度条 `AnchorScale`（评估表单内）

把「1–5 分 Radio」升级为可视化刻度：

```
 教学目标与内容准确性  ·权重 30%
 ●────○────○────○────○
 1    2    3    4    5
 需干预      合格      示范课
   ↑ 悬停任意档位浮出锚点卡：
   「3 · 合格：目标基本清晰，无实质性知识错误」
```

- 五档刻度联动质量色阶（score-1..5），选中档位放大落点；
- 锚点文案取 `constants/index.ts` 的 `DIMENSION_ANCHORS`（已冻结），逐档 tooltip 呈现——**这是把「评分体系专业度」外化为界面的核心控件**。

### 4.5 AI 视觉语言规范（全链路统一）

所有智能体产出的内容，必须同时满足以下三条识别规则，缺一不可：

1. **四芒星徽标 `AiBadge`**：12px 四芒星图标 + `--gradient-ai` 渐变填充 + 「AI 参考」/「AI 建议」文字；
2. **浅紫虚线卡片语法**：AI 卡片 = `--color-ai-bg` 浅底 + 1px `--color-ai` 40% 透明虚线描边 + 顶部 2px 渐变饰条——「虚线」隐喻「参考、未定案」，与人类督导的实线卡片形成语法对比；
3. **可追溯性露出**：AI 评分/建议必须露出 `confidence`（置信度条）与 `evidence`（转写引用块，等宽字体 + 浅底），低置信（`< 0.4`）与无证据的分**一律不渲染**（红线继承 AGENTS §9.6-4）。

```
┌╌╌╌╌╌╌╌╌╌╌╌╌╌╌╌╌╌╌╌╌╌╌╌╌╌╌╌╌╌┐
│ ✦ AI 参考 · qwen-audio-v1        │  ← 顶部渐变饰条 + 徽标行
│ 学生互动与参与      3.4 分      │
│ ▓▓▓▓▓▓▓▓▓░░░░  置信度 0.78      │
│ 依据（已脱敏转写）：             │
│ 「……第 12 分钟提问'谁来说说     │
│  这段代码的问题'，学生话轮 8 次」 │  ← evidence 引用块
└╌╌╌╌╌╌╌╌╌╌╌╌╌╌╌╌╌╌╌╌╌╌╌╌╌╌╌╌╌┘
```

**流式动效**：AI 对话与转写生成中用「渐隐三点 + 打字光标」，光标色 `--color-ai-bright`；转写 `pending/running` 态显示波形呼吸动画（§5.5）。

**占位规范（阶段②接口未就绪前）**：AI 区块展示为「预告卡」——徽标 + 「智能体评分将在阶段②接入」+ 灰紫骨架，**不得显示 0 分或空图表**（继承现有约束）。

### 4.6 动效规范（克制、有语义）

| 动效 | 参数 | 场景 | reduced-motion 降级 |
|------|------|------|-------------------|
| 数字进场 count-up | 600ms ease-out，一次/进页 | 双源罗盘综合分、驾驶舱关键数字 | 直接显示终值 |
| 雷达展开 | 400ms，从中心放散 | ScoreRadar 挂载 | 直接显示 |
| 罗盘弧生长 | 500ms stroke-dashoffset | QualityCompass 挂载 | 直接显示 |
| 转写波形呼吸 | 2s 无限循环，仅 opacity | TranscriptViewer pending/running | 静态占位 |
| AI 流式光标 | 800ms 闪烁 | AgentChat streaming | 常亮下划线 |
| 卡片悬浮 | `--shadow-card-hover`，位移 0 | 全部卡片 | 保留（非动效） |

动效总量控制：单页同时运动的元素 ≤ 2 处；禁止页面级滚动视差。

## 8. 红线与约束（不可违背）

以下既有规范在重设计中**全部继承，逐字有效**：

1. **评分展示 6 条硬规范**（AGENTS §9.6）：null ≠ 0；frontier 观测项处理；样本量必露；AI 必显形（低置信/无证据不渲染）；flags 不静默；伦理标注常驻；
2. **权限三原则 + 数据裁剪**：路由级 / 组件级（`v-if` 非 CSS 隐藏）/ 数据级（后端裁剪），教师仅可见本人；
3. **三态必备**：加载（骨架）/ 空（引导）/ 失败（重试），新增组件同样受约束；
4. **数字一致性**：综合分直接展示后端值，前端零重算、零四舍五入；
5. **音频权限**：教师不可听音频，只可见脱敏转写（界面按角色渲染，不靠前端遮挡兜底）；
6. **验收不回退**：`verify.sh` 143 项断言、`npm run lint/typecheck/test/build` 全绿是每个 Phase 的合入门槛；
7. **不引入第二套 UI 库**；评分色阶与 AI 色仅作语义使用，不作装饰。
