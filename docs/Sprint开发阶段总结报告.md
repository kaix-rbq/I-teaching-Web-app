## 1. 项目简介

### 1.1 项目定位

「爱教学」是面向高校的**教学质量全链路数字化管理平台**，围绕教学督导的真实业务走「三阶进化路线」：

| 阶段 | 主题 | 一句话目标 | 状态 |
|------|------|-----------|------|
| Sprint 1 | 查课程 | 课程信息透明可查、三角色数据打通、Web 框架稳定运行 | ✅ 已交付 |
| Sprint 2 | 看课堂 | 授课记录 + 课堂评价闭环；课堂录音、异步转写与智能体接入 | ✅ 已交付（见 §3/§4） |
| Sprint 3 | 帮教师 | 教学提优闭环：AI 评析、抽样复评、改进清单、反思、站内信、质量报告 | ✅ 核心闭环已落地（见 §5），少量旧排期项顺延 |

三类角色贯穿全部系统：**教研室主任（director）** 管本室课程与教师、**教师（teacher）** 管本人课程与提优、**督导（supervisor）** 全校听课评课。系统的核心架构设计是「**评分源可插拔**」：督导与 AI 只是 `evaluations.evaluator_type` 上的两个取值，向同一张表写同样结构，聚合层只认表不关心分数来源。

### 2.2 打下的技术地基（后续所有迭代的公共底座）

1. **六张基线表**：`departments / users / courses / course_classes / resources / supervision_plans`（schema.sql 为唯一事实源，禁 GORM AutoMigrate）。
2. **分层铁律**：`handler → service → repository → model` 单向依赖；数据范围裁剪只发生在后端 service 层，前端参数不构成权限（越权 `40302`）。
3. **统一响应信封与错误码表**（`pkg/errcode`）：错误码同时锁定 HTTP 状态语义（如 `40101` 锁 HTTP 401，保证 axios 拦截器正常跳登录）。
4. **契约先行工作流**：任何接口/表改动必须先改 `docs/backend_AGENTS.md` §8 / §13，再改代码；前端 `src/types/` 与后端 DTO 逐字对齐。
5. **种子数据与一键初始化**：`init_db.sh` 五步流程（建库→迁移→种子→bcrypt 覆写→自查），演示账号 director/teacher/supervisor 密码统一 123456。
6. **端到端验收**：`scripts/verify.sh` 首批断言覆盖 Sprint 1 三条故事线。

### 2.3 本阶段留下的工程约束（刻意的负空间）

## 5. Sprint 3「教学提优重构」（2026-10-16 ~ 10-21，PR #13/#14，16 个功能提交 + 2 次合并）

### 5.1 背景与决策冻结

10-16 发布《教学提优重构开发计划》（v1.0，**允许破坏性变更**），把需求仓促堆出来的「督导五维打分 + 双源融合」路线改为「**教师自建课 → AI 评课为主 → 抽样人工复评 → 教师提优闭环**」的现行业务流。关键决策（决策冻结表，20 组编号不许再议）：

- **B1/B2** 授课记录由教师自建 + 自录音；同一教师每满 5 条 AI 终评抽样 1 条交该课程负责督导人工评课（有高风险标签优先，否则取 AI 最低分）；
- **B8** **督导不打分**：只写评语建议，计分只按 AI 单口径；历史督导评分只读不进聚合；
- **B10** 弱化综合分：主视图以 AI 可观察维度（互动/参与/组织/提问讨论）为主；
- **B3/B4/B5** 上传者可回听本节录音；同一授课单条覆盖重传；浏览器录音只做前端演示原型；
- **D3** 新增 `ai_tasks` 任务表 + 状态查询/重试接口；**B12** 通知只做站内信，红点收敛 ≤2 处；**N9** 质量报告一页纸导出。
