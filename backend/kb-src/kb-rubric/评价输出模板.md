# 评价输出模板（S1 单次课 AI 评析，v1）

> 用途：定义 S1 单次课 AI 评析返回的 JSON 结构与四段评语写法。评分判断依据见同目录
> 《五维评分锚点.md》；本文件只规定“怎么输出”，不改变五维、权重与 1–5 标度。
> 适用 `formula_version = v1`、`prompt_version = v1`。

## 输出硬约束

1. **只输出一个纯 JSON 对象**：不要 Markdown 代码块、不要解释文字、不要注释、不要前后缀。
2. **维度必须完整**：`dimensions` 恰好包含 `objective`、`content`、`interaction`、`organization`、`frontier` 五个键，顺序固定，不得增删或改名。
3. **分数只能是 1–5 的整数或 `null`**：不接受 0、3.5、`"4"`、空字符串；无法从转写观测时写 `null`。
4. **非 `null` 必须有可定位引用**：每个非空维度至少 1 条 `quote`，且必须是脱敏转写中的**逐字子串**；定位失败一律视为无证据，该维应写 `null` 并加入 `notObservable`。
5. **`null` 与 `notObservable` 一致**：某维 `score = null` 时，`quotes` 必须为空数组、`confidence = 0`，并把该维 key 写入 `notObservable`。
6. **不要编造引用**：不能改写、概括、拼接、补全标点后当作原文；不要引用学生姓名、学号等个人信息。
7. **`citedChunks` 只填检索结果中真实存在的 chunk id**（如 `kb-rubric#3`）；没有检索结果就填 `[]`，不得自造。
8. **`riskTags` 只放高风险标签**（0–3 个），不要放普通缺点；教师端不可见，但仍不得写人身评价。
9. **四段评语必须是纯文本中文字符串**：不使用 Markdown、编号列表或换行；四段内容不得互相复制。
10. **不要输出服务端字段**：`promptVersion`、`modelVersion`、`schemaVersion`、`evidence` 由服务端注入，模型不得输出。

## JSON 结构

以下为结构示例，数值与引用仅示意；实际输出必须替换为本次课堂的真实结果。

      "quotes": [

      ]
    },
    "interaction": {
      "score": 2,
      "confidence": 0.71,
      "quotes": [
        {"start": 402.0, "end": 414.0, "quote": "大家听懂了吗？听懂了我们就继续往下讲。"}
      ]
    },
    "organization": {
      "score": 4,
      "confidence": 0.73,
      "quotes": [
        {"start": 1180.0, "end": 1192.0, "quote": "最后五分钟我们做一个总结，把今天的三条结论再对一遍。"}
      ]
    },
    "frontier": {
      "score": null,
      "confidence": 0.0,

  },
  "confidence": 0.68,

## 字段定义

| 字段 | 类型 | 必填 | 规则 |
|---|---|---|---|
| `dimensions` | object | 是 | 恰好五个维度键，顺序固定；每个值为维度对象 |
| `dimensions.*.score` | int 或 null | 是 | 1–5 整数；无法观测写 `null` |
| `dimensions.*.confidence` | number | 是 | 0–1，保留两位小数；`null` 维度必须为 0 |
| `dimensions.*.quotes` | array | 是 | 非空维度 1–3 条；`null` 维度必须 `[]` |
| `quotes[].start` | number | 是 | 起始秒，≥0，且小于 `end` |
| `quotes[].end` | number | 是 | 结束秒，必须落在转写时间范围内 |
| `quotes[].quote` | string | 是 | 10–80 字的逐字原文；不得改写或拼接 |
| `confidence` | number | 是 | 整条置信度 0–1；取非空维度置信度的最小值，全为 `null` 时为 0 |
| `comment` | string | 是 | 80–150 字总体评语 |
| `highlights` | string | 是 | 40–100 字，2–3 个具体亮点 |
| `improvements` | string | 是 | 40–100 字，1–3 个具体短板 |
| `suggestions` | string | 是 | 60–150 字，2–4 条可执行建议 |
| `notObservable` | string[] | 是 | 与 `score = null` 的维度完全一致，按固定顺序排列 |
| `citedChunks` | string[] | 是 | 只填本次检索真实命中的 id；无则 `[]` |
| `riskTags` | string[] | 是 | 0–3 个高风险短标签；无则 `[]` |

## 四段评语写法

| 字段 | 写什么 | 不要写什么 |
|---|---|---|
| `comment` | 总体判断： strongest 维度 + weakest 维度 + 一句整体建议；与五维分数一致 | 不要逐维复述分数；不要写“AI 认为”“根据转写”等模型自述 |
| `highlights` | 2–3 个**有原话支撑**的具体做法，如目标交代、案例、时间提示、追问 | 不要写“备课认真”“教态自然”等无法从转写验证的判断 |
| `improvements` | 1–3 个与最低分维度对应的具体短板，说明“哪里不足、影响什么” | 不要人身评价、不要笼统写“内容不够深入”；`null` 维度不要编造缺点 |
| `suggestions` | 2–4 条下一次可直接执行的动作，含方法、时机或频率 | 不要只写“加强互动”“提高深度”“多举例”这类无法执行的口号 |

写作要求：

- 四段各自独立，禁止把 `comment` 的一句话拆到另外三段重复使用。
- 评语面向教师，语气客观、具体、可复核；不使用讽刺、贬损或考核式表述。
- 引用证据中的原话可在评语中转述，但不要大段复制转写；评语不是证据字段。
- 若某维 `null`，在 `improvements`/`suggestions` 中只写“本节转写不足以判断”，不要推断该维差。
- 风险标签只给督导看；不要把风险标签原文写进教师可见的四段评语。

## 证据与置信度

### 引用怎么选

| 维度 | 优先引用 | 避免引用 |
|---|---|---|
| `objective` | 教师交代目标、重难点、总结回收目标的原话 | 泛泛的“大家注意一下” |
| `content` | 解释“为什么/怎么用”、案例、反例、适用条件的原话 | 只念标题或页码 |
| `interaction` | 开放问题、点名、等待、学生回答、追问、具体反馈 | 只有“对不对/听懂了吗”且无学生回应 |
| `organization` | 环节过渡、时间提示、任务指令、小结收尾 | “安静”“没人说话”等音量描述 |
| `frontier` | 具体论文、技术、产业案例、交叉应用及其与知识点的连接 | 只出现“人工智能/大数据”等热词 |

### 置信度怎么给

- `0.80–0.90`：多条直接证据，能明确支撑该分值。
- `0.60–0.79`：有直接证据，但只有一条或细节略弱。
- `0.40–0.59`：只有间接线索，或转写片段不完整。
- `< 0.40`：不要给分；写 `null` 并加入 `notObservable`。
- 整条 `confidence` 取所有非空维度置信度的**最小值**，避免用高分维度掩盖弱证据；全为 `null` 时写 0。

### 风险标签

只在出现需要督导重点关注的高风险情况时使用，建议用 2–6 个字的短标签，例如：

- `学生参与度低`：有明确证据表明学生长期无回应或互动严重不足；
- `内容准确性风险`：出现可识别的知识性错误且未纠正；
- `课堂节奏失衡`：严重拖堂、提前结束或关键环节缺失。

普通缺点写进 `improvements`，不要滥发风险标签；没有高风险就填 `[]`。

## 自检清单（返回前逐项检查）

1. 是否是**纯 JSON**，没有代码围栏、解释文字或注释？
2. `dimensions` 是否恰好五个键，且拼写、顺序正确？
3. 每个 `score` 是否为 1–5 整数或 `null`？
4. 每个非 `null` 维度是否至少 1 条 `quote`，且能在转写中逐字找到？
5. 每个 `null` 维度是否 `confidence = 0`、`quotes = []`，并出现在 `notObservable` 中？
6. `notObservable` 是否没有多余项、没有重复、顺序正确？
7. 四段评语是否具体、互不重复，且没有模型自述或人身评价？
8. `citedChunks` 是否只含本次检索真实命中的 id？
9. 是否误输出了 `promptVersion`、`modelVersion`、`schemaVersion` 或 `evidence`？

任何一项不通过，先修正再返回；不要返回半成品或“说明文字 + JSON”。

## 维护约定

- 本文件为 **v1**，与 `prompt_version = v1`、`formula_version = v1` 对齐。
- 新增/删除 JSON 字段时必须同步 `internal/agent/eval.go` 的解析结构、`internal/agent/prompt.go` 的输出示例与本文档；只改文档会导致解析失败或字段丢失。
- 本文件只定义输出格式；维度分档与判定标准以《五维评分锚点.md》为准，两者不得互相替代。
